# Practice system

The rules-backed core is `packages/web/src/education/practice.ts`; the approved interactive surface is `packages/web/src/practice-ui.ts`. Practice exposes all 13 curated exercises across eight implemented categories. The catalog remains a starter corpus: generated puzzles, public content authoring, progressively harder advanced corpora, and strategic assessments require separate validation and implementation.

The view follows the approved Practice design: actual tile faces, a visible hand, answer selection, explanatory feedback, and an explicit next-exercise action. Native category/exercise selectors allow direct access without prerequisite locks. Wait and ukeire exercises offer all 34 tile types initially; after a correct answer they show only the learner's selected answers, matching the approved feedback composition. Recognition, shape, shanten, yaku, scoring, and one-opponent defense use the same visual structure with the appropriate response control.

Without an explicit exercise or a resumable session, initial selection uses the transparent recommendation model: due reviews first (oldest due first), then unseen exercises in catalog order, restricted to the requested skill when supplied. The evidence disclosure also offers `Recommended practice` for the next eligible exercise, excluding the current item. `Next exercise` continues within the selected category. These suggestions never lock or hide other exercises and do not imply an expert-level assessment.

`Check answer` records a graded response. Incorrect answers stay on the same exercise and can be changed and retried; correct answers expose `Next exercise` and never silently advance. Empty numeric/shape submissions request an answer without fabricating a practice attempt. Explanations and the help control mark the response assisted; after feedback reveals the explanation, retries are assisted too. Immediate revisits within the mounted view also remain assisted. Independent accuracy excludes both hints and retries.

`createPracticeView` accepts validated progress, an initial exercise or skill, a tile renderer, navigation callbacks, and a progress-change callback. Its optional `renderSupplement` hook keeps App-owned saved-decision controls present when an answer or exercise change rerenders the view. Successful feedback moves the explicit Next action into the nearest visible area without smooth motion. Guests can use its default local persistence. The App supplies owner-aware persistence with `persistLocally: false` and an account-scoped `sessionKey`, so opening an account's practice does not overwrite the guest store. The view never authenticates users or makes network requests itself. The App owns account synchronization and related error/retry behavior.

The bounded `openmahjong.practice-session.v1` session records the active exercise/content version, selected response, attempt count, assistance, and the last attempt identity. Reload preserves the exercise and the distinction between a retry and an independent first response. A completed view is restored only when its stored response still grades correct and a matching correct attempt exists in the supplied progress. Invalid or blocked local storage cannot prevent in-memory practice.

Schema version 1 exercises contain stable ID, content version, explicit ruleset reference, skill, difficulty, prompt, original explanation, provenance, exact expected answer, and a discriminated visible position. Current kinds: recognition, complete shape, shanten, waits, ukeire, yaku, scoring, and one-opponent genbutsu. The legal response domain follows the kind: recognition indices; booleans for shape; integer shanten/points; tile types for waits/ukeire/defense; yaku IDs for yaku recognition. Selection order is immaterial; strings are never coerced to numeric tile IDs.

`validateExercise` checks bounded inputs, supported ruleset, instructional metadata, physical copy limits, valid hand dimensions, and consistency between the independently authored answer and rules calculations. `checkPracticeAnswer` refuses exercises that fail the gate and returns correctness, exact expected answer, explanation, and supported numeric facts. The gate is required for future generated content too; a generator alone is not validation. Runtime content is currently curated only, so adding a generated provenance type requires an explicit extension and tests.

These are hand-based exercises/public table fragments, not fabricated complete game states. Actual lesson/game scenarios remain seed-driven through the engine. Structural waits include mathematically valid completions even if all copies are seen. Ukeire counts only improving types with unseen copies, and its feedback labels counts as unseen, never as known live-wall contents. Visible counts exclude the learner's hand and count physical tiles once. Genbutsu guarantees apply only to the named locked riichi opponent's ron; no guarantee is made against other opponents or tsumo.

## Curated fixtures

There are 13 original starter exercises: two recognition, two shapes, two shanten, two waits, one visible-count ukeire, one yaku, two scoring, and one defense. Each authored expected answer is recalculated in `education.test.ts`. The explicit winning tile and win context matter; changing either can change fu or yaku.

- Single wait: `123m123p123s777z5m` needs only 5m. With two extra visible 5m, one copy remains unseen; with three, none do.
- Two-sided wait: `123m123p777z55s45m` accepts 3m/6m.
- Riichi/pinfu ron: `234m345p345s789s22s`, won on 2m by a nondealer, no bonuses: 2 han, 30 fu, 2,000 points. The 9s prevents tanyao; the exact winning tile establishes the two-sided interpretation.
- Seven-pairs ron: `22m55m33p77p33s77s22z`, won on South by a nondealer, no bonuses: 2 han, 25 fu, 1,600 points.

A complete practice curriculum still needs progressively harder corpora, more invalid counterexamples, calling/riichi/push-fold/situational categories, and validated exercises derived from the actual reviewed position. A review can point to a related skill without claiming that an unrelated curated hand is the original decision. A numeric answer matching this engine does not establish that the engine is independently correct in every edge case; maintain human derivations and rule-specific regressions. `practice-ui.test.ts` exercises all curated answers through their actual controls, wrong-answer/retry and reload behavior, assisted evidence, duplicate-submit handling, and account/guest persistence isolation. Browser geometry, keyboard, and accessibility evidence are recorded separately in the UX audit.
